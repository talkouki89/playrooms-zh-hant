# 技術說明：Playrooms 繁體中文化怎麼做的

本文記錄這個漢化是怎麼把中文塞進 Unity IL2CPP 遊戲的，方便日後遊戲更新、或有人想
移植到其他 Unity Localization 遊戲時參考。

## 1. 目標結構

| 項目 | 值 |
|---|---|
| Engine | Unity **6000.6.3f1** |
| Scripting | IL2CPP（`GameAssembly.dll` + `global-metadata.dat`，metadata 版本 108） |
| 文字系統 | `com.unity.localization`（String Table + Locale 資產） |
| 資源系統 | Addressables 2.11.2（`StreamingAssets\aa\catalog.bin` + bundle） |
| 文字渲染 | TextMeshPro（342 個 `TextMeshProUGUI`，沒有 legacy `UI.Text`） |
| 遊戲版本 | 1.0.2 |

`Player.log` 位於 `%USERPROFILE%\AppData\LocalLow\Two Pixels UG (haftungsbeschränkt)\Playrooms\`，
排錯時很好用。

## 2. 文字在哪裡

`Playrooms_Data\StreamingAssets\aa\StandaloneWindows64\` 底下每個語系一個 bundle：

```
localization-string-tables-english(en)_assets_all.bundle
localization-string-tables-french(fr)_assets_all.bundle
localization-string-tables-german(de)_assets_all.bundle
localization-string-tables-italian(it)_assets_all.bundle
localization-string-tables-portuguese(brazil)(pt-br)_assets_all.bundle
localization-string-tables-spanish(es)_assets_all.bundle
```

每個 bundle 內含 6 個 `StringTable` MonoBehaviour（`General_en` … `Popups_en`），
欄位是 `m_LocaleId.m_Code`、`m_Name`、`m_TableData[]`，每個 entry 有 `m_Id`（key 的雜湊）
與 `m_Localized`（要顯示的字）。

因此漢化只需要：**把英文表每個 `m_Localized` 換成中文**，`m_Id` 完全不動，
遊戲端查表邏輯不必修改。

Locale 顯示名稱在 `localization-locales_assets_all.bundle`，`Locale` 資產的
`m_LocaleName`（語言選單顯示的字）與 `m_Identifier.m_Code`（`en`）。
把 `m_LocaleName` 改成 `繁體中文`，選單就會顯示中文；`m_Code` 必須保持 `en`，
否則 String Table 對不上。

## 3. 字型問題（最關鍵）

遊戲用三套 TMP 字型資產：

| 資產 | 原圖集 | 原本字數 | 備註 |
|---|---|---|---|
| `RobotoCondensed-Regular SDF` | 512×512 Alpha8 | 228 | 主要內文 |
| `RobotoCondensed-Bold SDF` | 512×512 Alpha8 | 228 | 標題 |
| `VT323 SDF` | 1×1（動態佔位） | 0 | 復古像素字 |
| `Anton SDF` | 1024×1024（動態佔位） | 0 | 大型標題 |

拉丁字型不含 CJK 字形，直接換文字只會看到 `□`（TMP 會把缺字換成 U+25A1，
`Player.log` 也會印 `The character with Unicode value \u8A2D was not found ...`）。

### 解法：DynamicOS

TMP 3.2 的 `m_AtlasPopulationMode` 有三種：`Static=0`、`Dynamic=1`、`DynamicOS=2`。
`DynamicOS` 不需要把 TTF 塞進 asset bundle，而是用 **作業系統字型家族名稱** 在執行時
透過 TextCore 的 `LoadFontFace(familyName, styleName, size)` 載入字型，再把缺的字
即時繪進圖集。本漢化因此把每個字型資產改成：

```
m_AtlasPopulationMode      = 2          # DynamicOS
InternalDynamicOS          = true
m_IsMultiAtlasTexturesEnabled = true
m_FaceInfo.m_FamilyName    = "Microsoft JhengHei"
m_FaceInfo.m_StyleName     = "Regular" / "Bold"（依資產名稱）
m_SourceFontFile           = (0, 0)
m_GlyphTable / m_CharacterTable / m_UsedGlyphRects = []   # 清掉烘焙的拉丁字
m_FreeGlyphRects           = [{0,0,2048,2048}]
m_AtlasWidth/Height        = 2048
```

同時把對應的 atlas `Texture2D` 改成 2048×2048、`Alpha8`、可讀（`m_IsReadable=true`）、
資料清空，並把材質的 `_TextureWidth/_TextureHeight` 改成 2048，這樣 TMP 才能寫入
新產生的字形。

> 為什麼要清空烘焙字表：只要 `m_CharacterTable` 還留著舊條目，TMP 就不會去問 OS 字型，
> 而是直接畫舊圖集裡的位置；而那些位置在新圖集裡是空的，結果就是「中文正常、英文變空白」。
> 這是實測踩到的坑。

圖集容量：`2048² ÷ (44pt + 2×5 padding)² ≈ 1400` 個字形，足夠本作全部中文；
不夠時 TMP 還會自行建立新圖集（multi-atlas）。

## 4. Addressables 的 CRC

改過的 bundle 一開始會被拒絕載入，`Player.log` 會出現：

```
CRC Mismatch. Provided 8cb0629b, calculated 0d09e075 from data.
Will not load AssetBundle 'aa\StandaloneWindows64\localization-locales_assets_all.bundle'
```

Unity 的 AssetBundle CRC 算法不是 zlib/crc32c 的常見變體，短時間內無法重算，
因此改成 **把 catalog 裡該 bundle 的 CRC 欄位設為 0**（`crc=0` 代表不做檢查）。

`catalog.bin`（Addressables 2.x binary catalog）中，每個
`AssetBundleRequestOptions` 記錄大致是：

```
[u32 hashOff][u32 hashStrOff][u32 crc][u32 bundleSize][u32 a][u32 b]
[u32 selfOffset][u32 nameOff][u32 internalIdOff][u32 flags]...
```

`selfOffset == 記錄起始位址` 可以拿來定位記錄；`crc` 就在 `bundleSize` 前面。
實務上更簡單可靠的做法：**在 catalog 裡搜尋「原始 bundle 大小」的 uint32，
它前面那個 uint32 就是 CRC**（本作 bundle 大小互不相同，命中率 100%）。

## 5. 工具實作流程（`tools/patchlib.py`）

1. `ensure_backup()`：第一次執行時把 9 個會被改的檔案複製到 `.backup\Playrooms\`。
2. `restore_from_backup()`：每次套用前先把原檔還原，保證可重複執行。
3. `patch_string_tables()`：讀 `translations\zh-Hant\*.tsv`，逐條覆寫 `m_Localized`
   （`\n` 還原成真換行），存回 bundle（`env.file.save(packer="lz4")`）。
4. `rename_locale()`：把 `m_LocaleName` 改為 `繁體中文`。
5. `patch_fonts_in_file()`：主資源檔沒有 MonoBehaviour 型別樹，所以先從 bundle
   「借」一份 `TMP_FontAsset` 的 typetree（`obj.serialized_type.nodes`），
   再用 `read_typetree(nodes=...)` 解析主檔內的 MonoBehaviour。
6. `disable_crc_checks()`：見上一節。

## 6. 已知限制

- **版本相依**：`FONT_PIDS` 用的是這個 build 的 path id。遊戲更新後若 path id 變了，
  腳本會找不到字型（不會亂改），需要重新抓一次 id（把 `FONT_PIDS` 對應檔案的值改成 `None`
  可以用「全掃描」模式，只是慢一點）。
- **字型風格改變**：中文由微軟正黑體產生，原本的像素風（VT323）與 Roboto 都被取代。
  想換字型改 `FONT_FAMILY` 即可（需系統已安裝該字型，且含 CJK 字形）。
- **只換掉英文槽**：語言選單不再有 English。要並存需要重建 Locale 與 catalog
  條目（Addressables 的 key/entry 都要新增），成本高很多。
- **UI 長度**：中文比英文短，個別按鈕可能看起來偏鬆；若要微調直接改譯文。
- **Steam 驗證/更新**會覆蓋檔案，重跑一次即可。

## 7. 驗證方式

1. `Player.log` 不應再出現 `CRC Mismatch` 或 `... was not found in the [...] font asset`。
2. 進遊戲看：啟動畫面「按任意鍵開始」、主選單、設定五個分頁（音訊／玩法／圖像／
   無障礙設定／操作）、存檔欄位、遊戲模式選擇、遊戲內 `mail.exe` 郵件、Balli 對話。
3. 特別檢查混排字串：`反轉 Y 軸`、`隱藏 HUD（拍照模式）`、`Balli 節慶服裝`、
   `SMAA`、`light.exe`。
